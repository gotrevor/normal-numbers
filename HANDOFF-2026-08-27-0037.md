## 🧠 Context to carry forward

**The originally-briefed approach doesn't work as literally stated.** The brief
suggested forcing "long zero runs" (mimicking `NormalMeager.lean`'s
`longZeroRunOpen`) to make `digitTV` small. That's backwards: forcing digits to
all be `0` makes the histogram *maximally* skewed, so `digitTV → 1`, not `→ 0`.
I substituted the correct forcing target: a **periodic balanced block**
`0,1,…,b-1,0,1,…` repeated `t` times (`periodicPattern` in the file) — each
residue occurs exactly `t` times, so forcing it drives `digitTV` toward `0` as
`t` grows relative to the arbitrary prefix `p`. Everything downstream (the
open/dense cylinder shape) needs this substituted target, not the brief's
literal zero-run wording.

**The math that's now fully proved (safe to build on without re-deriving):**
- `digitTV_le_of_tail_periodic`: if digits `[p, p+b*t)` spell out the periodic
  pattern, `digitTV b x (p+b*t) ≤ p/(p+b*t) + b*|t/(p+b*t) - 1/b|` — the
  arbitrary first-`p`-digit histogram contributes at most `p` total slop.
- `digitTV_le_periodic_sq`: plugging `t := p*p` collapses this to the clean
  closed form `digitTV b x (p + b*p²) ≤ 2/(1+b*p)`, which → 0 as `p → ∞` and
  is what the Baire density argument and the final schedule both need.
- `card_residue_range`: among `[0, b*t)`, each residue `< b` occurs exactly `t`
  times (bijection `q ↦ c + b*q`, **not** `q*b+c` — I hit `omega`/`Nat.eq_of_mul_eq_mul_*`
  friction with the latter order; `c + b*q` matches `Nat.div_add_mod`'s and
  `Nat.add_mul_mod_self_left`'s argument order directly).

## ⚠️ Gotchas

- **`rw`/`simp` need exact syntactic match, not just defeq.** Repeated friction
  this session: `Finset.filter_map`'s output is stated via `∘` composition
  (`(fun i => ...) ∘ ⇑f`), which doesn't `rw` against a hand-written
  `fun j => ... (f j) ...` even though they're defeq — need
  `simp only [Function.comp, addLeftEmbedding_apply]` first to normalize.
  Similarly `set x := e with hx` folds *all* syntactic occurrences of `e`
  everywhere (including ones you didn't mean to fold) — use `conv_rhs =>` or
  `conv_lhs =>` to scope it, or just avoid `set` when the pattern also appears
  where you don't want it touched (bit me with `Finset.card_range p` rewriting
  `p` itself inside an unrelated `range p`).
