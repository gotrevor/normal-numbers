## 🧠 Context to carry forward

**The shape of the finished proof.**  Vandehey's own §3 hot-spot criterion is *not used at all*.
The project had been carrying a debt against it (a "tightness-corrected criterion" plus tightness
of a CF-normal point's empirical measures) since the first laps.  That debt is void: Serret +
Smith reduce Thm 1.1 to `x ↦ D·x` for prime `D`, and there the concrete Raney `L/R` transducer
supplies everything.  Anyone reading old notes will find the §3 language and should ignore it —
I corrected the `LiteratureVandehey.lean` docstring at `43e39ba` precisely because it was still
asserting the abandoned route.

**Why the clock, not the stream.**  The lap-6 finding still governs: the machine emits `L/R`
*letters*, the image's CF digits are the *runs*, and the letter count per input digit has
infinite mean, so no `hlen` exists for the letter clock and no digit-emitting finite-state
transducer exists either.  `mobiusUniformFreq_of_runClock` dissolves this by never asking the
automaton to *produce* the output stream — `MobiusUniformFreq` already talks about `cfDigit` of
the image directly.  All that is needed is a monotone clock with a positive `x`-independent rate
plus a Cesàro count sampled along it.  If you ever revisit this area, do not try to resurrect
`hout`/`hcof`; they are false for this machine.

**How `hcount` actually went down** (`VandeheyCFBridge.lean`).  One chain of bounded differences,
every constant a function of `D` and `|v|` only.  The two non-obvious steps:

- *The low end of the run window is free.*  I expected to pay a constant for positions below
  `lrPos img 1 − 1`; there are in fact **zero** occurrences there.  `cf_of_patWord_occ` forces
  `P + 1 = lrPos (runIdx P + 1)` with `runIdx P + 1 ≥ 1`, so `P ≥ lrPos 1 − 1` is automatic.
  This matters because `lrPos img 1 = cfDigit img 0` is *unbounded* — a constant-slack argument
  there would not have worked, and the lap-8 plan's step 2 was right to flag it.
- *`runIdx` is monotone for every real.*  `runIdx w P = Nat.findGreatest (fun n => lrPos w n ≤ P) P`
  — predicate only weakens as `P` grows, bound only grows, so `Nat.findGreatest_mono` applies
  with no irrationality hypothesis (`runIdx_mono'`).  The pre-existing `runIdx_mono` needed
  `Irrational w`, which would have forced an ugly `if Irrational x then … else n` clock to meet
  the *unconditional* `hmono` of `mobiusUniformFreq_of_runClock`.  Finding this was the one real
  simplification of the lap; without it the capstone is noticeably uglier.

**Structural decision made this session.**  `vandeheyUniformFreq_holds` and
`vandehey_matrix_action_holds` were **moved out** of `LiteratureVandehey.lean` into a new
`VandeheyCapstone.lean`.  They cannot be proved in place: every module of the Raney chain imports
`LiteratureVandehey` for the frozen `VandeheyUniformFreq` / `vandehey_matrix_action` statements,
so proving the crux there is an import cycle.  The frozen statements and the endgame reduction
`vandehey_matrix_action_of_uniformFreq` stayed byte-identical where they were, per the standing
freeze rule.  If a future lap wants them back in one file, the only way is to split the frozen
`Prop`s into their own leaf module — I judged that churn not worth it.

## ⚠️ Gotchas

- **Never run two `lake build`s at once on this box.**  It reliably reproduces
  "resource exhausted (error code 24, too many open files)", and worse, it can invalidate mathlib
  traces and provoke a wide cold rebuild that then fails the same way.  A plain retry loop
  (`for i in 1 2 3; do … done`) recovers.  See the corpus note
  `lean-box-fd-exhaustion-is-mmap-not-nofile.md`.
- `set x := e with h` folds `e` only into hypotheses that **already exist**.  `obtain` everything
  first, `set` last.  The tell when you get this wrong is an `omega` failure whose `where` block
  lists the same mathematical quantity under two atom letters.
- `div_add_div_same` is shadowed inside `NormalNumbers.VandeheyLR`; use `ring`.
- `Finset.card_filter_add_card_filter_not` takes ONE explicit argument (the set).
- `occStart` filters over `Finset.range`; to meet a `Finset.Ico 0 N` goal, `rw [← Finset.range_eq_Ico]`
  **before** `Finset.filter_congr`.
