## 🧠 Context to carry forward

The mathematical shape that made this work, in case the constants ever need re-tuning:

- The dimension bound `K·(log y / log max(2,t))^k` splits at `p = 2h`.  Below `2h` the factors
  `(1-h/p)⁻¹ = p/(p-h)` are *not* small and must be handled by an exact identity, not an estimate:
  the subproduct is dominated by the full integer interval `∏_{m=h+1}^{2h} m/(m-h) = C(2h,h) ≤ 4^h`.
  Any attempt to bound these by `exp(2h/p)` fails outright (`h/p` is not `< 1/2` there).
- Above `2h` it is `exp(2h·∑1/p)`, and the whole analytic content is
  `∑_{v<p≤y} 1/p ≤ 8 + 12 log(log y/log v)`, built from `mertens_crude` by log-dyadic blocks
  `(v,v²]` (mass `≤ 8` each) and `⌈log₂ L⌉` blocks to cover.
- **Dead end worth remembering**: my first plan reduced the real cutoff `t` to a natural `m = ⌊t⌋₊`
  so the block induction could run over naturals.  That loses up to `log 2` of `log v` per use, and
  the resulting constant overshoots `24h` — the slack in `8/log 2 = 11.54 ≤ 12` is only ~4%.  The
  fix (and what is in the file) is to run the *entire* block machinery with a **real** `v`, flooring
  only inside the Mertens call at `⌊v²⌋₊`, where the loss is harmless because `log⌊v²⌋ ≤ 2 log v`
  is still exact in the needed direction.
- Constants came out exactly as `papers/prime-model-sieve-assessment.md` predicted.  That document's
  dimension-input section can now be marked discharged.
