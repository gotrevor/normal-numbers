## 🧠 Context to carry forward

The one idea worth keeping. The kickoff proposed proving the symmetrization identity
`∑_{|S|=j} (-1)^{|S∩W|} = K_j(|W|)` by counting `j`-subsets against the window set, with `K_j`
the explicit Krawtchouk sum `∑_i (-1)^i C(w,i) C(L-w,j-i)`. **Don't.** Work in `ℝ[X]` instead:

```
∏_{i<L} (1 + ε_i X)   with ε_i = -1 on W
  = (1-X)^{|W|} (1+X)^{L-|W|}        (split the product over filter (· ∈ W))
  = ∑_{S ⊆ range L} (-1)^{|S∩W|} X^{|S|}   (Finset.prod_add)
```

Define `kraw L j w := ((1-X)^w * (1+X)^(L-w)).coeff j` and equate coefficient `j`. The
"depends only on the weight" property becomes *definitional*, no bijection is built, and the
explicit Krawtchouk sum never appears anywhere in the file. This collapsed what the kickoff
budgeted as the hard step into ~25 lines.

Everything downstream is then exact at every finite `N`, mirroring `Walsh.blockMean_eq`:
`symParityMean_eq` (forward) and `onesFreq_eq` (inverse), so both directions of the headline are a
finite linear combination of limits. Forward needs `∑_w kraw L j w · C(L,w) = 0` for `j ≥ 1`;
inverse needs cube orthogonality, which is Walsh's existing `sum_neg_one_pow_inter_eq_zero` applied
to `symmDiff T W` (the pointwise `(-1)^{|T∩S|}(-1)^{|W∩S|} = (-1)^{|(T Δ W)∩S|}` check is a
four-way `by_cases` on membership, not a cardinality identity). The `j = 0` column is
`symParityMean s L 0 N = 1`, which is what produces the `C(L,w)` in the limit.

Approach abandoned: proving the four finite statements by `decide`. It cannot work — see Gotchas.

The `separation_four` witness is the kickoff's ±1 word list rewritten in closed form:
`sepWord w = 1/16` if `w 1 = w 2`, else `2/16` or `0` by the parity of `w 0 + w 1 + w 3`. I derived
the parity form by tabulating the eight listed words; it is what lets `norm_num +decide` discharge
all 15 abelian equations uniformly instead of 16 membership tests.

## ⚠️ Gotchas

- **`decide` cannot reduce `Finset.univ : Finset (Fin n → Fin k)`.** It bottoms out at
  `Multiset.Pi.cons` (via `Fintype.piFinset`) even for 16 elements. This is why `sum_fun_cons` /
  `sum_fun3` / `sum_fun4` exist — split by first letter with `Fin.consEquiv`, then
  `Fin.sum_univ_two` + `norm_num +decide [Matrix.cons_val_*]`. `+decide` *is* fine for
  `Finset.card`-of-filter over `Fin n`.
- **`fin_cases` emits `⟨0, ⋯⟩`, not `0`.** `linarith` then fails with all the right equations in
  context. `simp only [Fin.zero_eta, Fin.mk_one, Fin.isValue]` before `linarith` fixes it. This
  cost a full debug cycle on `rigid_three`.
- Mathlib v4.33.1 name drift hit here: `Finset.card_sdiff` now states
  `#(s \ t) = #s - #(t ∩ s)` (no subset hypothesis); `Polynomial.finset_sum_coeff` is deprecated
  for `finsetSum_coeff`.
- The stop gate declines a plain `box done` while *any* `src/` sorry remains. For a scoped run
  whose target is clean, `box done --green` is the correct exit.
