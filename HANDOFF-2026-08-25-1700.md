## Gotchas (this lap)

- **Nested `Exists.choose`/`obtain` mismatch**: if a term references
  `foo.choose_spec.2.2.choose` (e.g. inside a `def` via `dif_pos`), do NOT
  `obtain ⟨...⟩ := foo.choose_spec` in the proof — the destructured
  variables are NOT syntactically the same as the `.choose` projections
  used elsewhere, and `rw` will fail with a motive/type-mismatch error. Use
  `set W := foo`, then chain `.choose`/`.choose_spec` projections
  consistently (never `obtain`) so every occurrence stays syntactically
  aligned. See `dBlock_spec`'s proof.
- **`List.map_map` + comp-form mismatch**: after `rw [List.map_map]`, a
  goal has `f ∘ g` (composition), not `fun x => f (g x)` (lambda) — even
  though defeq, `rw` with a lemma stated as the lambda form won't match.
  Fix: `simp only [Function.comp_def]` right after `List.map_map` to unfold
  comp back to lambda form before further `rw`s.
- **`(l.take n).map f = (l.map f).take n`** is `List.map_take` (that
  direction — not the reverse). `(range n).take m = range m` (for `m≤n`) has
  no named mathlib lemma; prove via `List.ext_getElem` + `simp`/`omega` (2
  lines, robust — don't hunt for a `range_take` lemma, there isn't one).
- **`div_le_div_iff₀ h1 h2` infers denominators from `h1`/`h2`'s TYPES**, not
  position — passing `hε5 : 0 < ε/5` as the second arg makes Lean unify the
  second fraction's denominator as `ε/5`, not `5`. Always pass an explicit
  `(by norm_num : (0:ℝ) < 5)`-style proof of the LITERAL denominator you want.
- **`Nat.mul_add_mod_self_left n b a : (n*b+a)%n = a%n`** — divisor must be
  the FIRST factor of the product for this exact lemma; `Nat.mul_add_mod_
  self_right b n a : (b*n+a)%n=a%n` has it as the SECOND. Check which side
  your product has the modulus on before reaching for either.
- When a `have h : X := by tac` reduces to EXACTLY a hypothesis already in
  context (after `rw` auto-closes via `rfl`), a trailing tactic like `ring`
  errors "no goals to be solved" — just write `have h : X := hyp` directly,
  skip the `by` block.
