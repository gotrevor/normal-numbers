## One message, one new file

Filename: YYYYMMDDTHHMMSSZ-SENDER-UUID.md

Use the actual UTC clock and a fresh UUID, not an estimated time.  Example:
20260922T174110Z-astra-01c73df4-4e1b-46bd-bfe8-8a8db44a3287.md

Contents:

    From: astra
    To: fable
    UTC: 2026-09-22T17:41:10Z
    Reply-to: none
    Subject: One specific question or result

    Your message.  Include exact statements, evidence and file references
    when needed.  End with a clear question or next action, if any.

For a reply, Reply-to is the exact basename of the message being answered.
Messages go only to your counterpart; use their role in To.

Finish writing the complete file, then chmod 444 that exact file to publish.
Readers consume ONLY read-only .md files.  Thus an unfinished writable file
is not yet mail.  Never edit, append to, rename, delete or make writable a
published file.  Corrections and acknowledgements are NEW messages.
Read-only permissions are an accidental-edit guard, not tamper-proof storage.

## Conversation loop

1. At startup, read this lane's published messages; send one short introduction
   with your current target or question.
2. Check for new counterpart messages before substantial work, after a
   meaningful result, and before reporting back to Trevor.  A filename you
   already read need not be read again.
3. Answer unresolved questions or send a substantive finding.  Do not create
   acknowledgement-only ping-pong or repeat unchanged status.
4. If actually waiting on your counterpart, poll about once a minute using
   your session's wait mechanism.  No daemon, notification service or busy loop.
   A file does not wake another agent automatically.
5. Before ending your session, send a handoff with current result, remaining
   question and relevant commit/file references.

There is no mutable index, cursor file or shared transcript.  Timestamped
filenames order the conversation; Reply-to identifies its branches.
This is coordination, not permission to change a counterpart's files or launch
new jobs.  Negotiate ownership before overlapping edits.  Report "sent" only
after the published file exists; "read" only after you have read it.

Messages are eligible for git tracking.  Commit your own completed files
without sweeping another worker's unfinished changes.  Never rewrite message
history to tidy a conversation.  Keep credentials out of mail.
