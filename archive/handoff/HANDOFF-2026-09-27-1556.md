## 🧠 Context to carry forward

**The pipeline, and where §4 sits.**  `evenEncoding` (§2, proved earlier at `7f05cb2`) returns a
depth `s` and an exponent `a`; §4 must consume **both** — `r = s − 1` is the survivor slot and
`2a` is the divisor count every coordinate then reads at its own scale.  §4 itself is pure
arithmetic; the first unavoidably analytic input is the *prime selection* that feeds it (next
actions).  Do not conflate the two: a green §4 is not evidence about AGP.

**Why the contract looks the way it does.**  The primes (`q`, the families `p j t`) are
**parameters**, not constructed.  That is deliberate: §4's later caller must avoid, for each
exceptional AGP modulus, one of its prime divisors, so the selection cannot be fixed here (and
must never be "the next `k²` consecutive primes").  The family is a plain function
`ℕ → ℕ → ℕ` with hypotheses only on the valid index set `j < k, j ≠ r, t < j+1`, so a caller
holding a `Finset`-indexed injection can extend it arbitrarily off-index.

**What was genuinely new versus the inherited scalar (base-2) proof.**  The scalar construction
pinned a valuation from `m ≡ q^e [MOD q^(e+1)]` (`SwingC2.factorization_eq_of_modEq`).  Here the
CRT condition is modulo a **product** `P_j^c`, so at a single prime `p = p j t` it reads
`n ≡ p^(c−1)·W^(c−1) [MOD p^c]` with `W` the other `j` primes.  Hence the new
`factorization_eq_of_modEq_unit`.  Everything else is bookkeeping: `exists_crt_shifted`
(coprime moduli with *free* target residues, so slot `r` carries `q^a` and killed slots carry
`P_j^c` in one system), `prime_not_dvd_both`, `tau_prime_pow_mul_prime`.

**Two points that are not automatic** — a future reader will be tempted to "simplify" them away:

- `u < B`.  `Q ∣ R+r` and `R < A = QB` only give `u ≤ B`.  Strictness comes from the residue: if
  `R+r = A + d` then `(R+r) % q^a = d < r`, whereas the CRT condition forces
  `(R+r) % q^a = Q > r`.  This is the *only* place `r < q^(a−1)` is used (plus `0 < u`), and it
  is exactly the paper's "as `Q > r` eventually".
- `0 < R`.  Runs through the killed slot `j = 0`, available precisely because `r ≥ 1`: `R = 0`
  would force `P_0^c ∣ P_0^(c−1)` with `P_0 ≥ 2`.

**Approach not taken.**  I did not try `Prime.dvd_finset_prod_iff` for `¬ p ∣ W`; going through
`Nat.Coprime.prod_right` + `Nat.Prime.coprime_iff_not_dvd` avoided a name gamble and is shorter.
